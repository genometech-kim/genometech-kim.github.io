# News 게시물 수정

News 페이지 데이터(`src/data/news.ts`)에서 기존 게시물을 수정하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 무엇을 바꿀지 명확히 확인한 뒤에만 수정한다.

## 입력

`$ARGUMENTS`에 수정할 게시물의 id 또는 제목 일부가 있으면 그것을 사용한다. 없으면 물어본다.

```
/edit-news 4
/edit-news 우수신진과제
```

## 절차

1. `src/data/news.ts`를 읽는다.
2. 입력받은 값으로 `id`(정확히 일치) 또는 `title`(부분 일치, 대소문자 무시)을 대조해 대상을 찾는다.
   - 일치하는 게시물이 없으면 다시 확인해달라고 요청한다. 임의로 비슷한 게시물을 골라 진행하지 않는다.
   - 제목으로 찾을 때 후보가 여러 개면 후보 목록(id/제목/뉴스 날짜/업로드일)을 보여주고 선택해달라고 물어본다.
3. 대상이 하나로 정해지면, 현재 정보(제목, 뉴스 날짜, 업로드일, 내용, 이미지 지정 여부)를 보여주고 무엇을 바꿀지 물어본다. 가능한 변경 종류:
   - 제목 수정
   - 뉴스 날짜 수정 (형식 `YYYY.MM` 또는 `YYYY.MM.DD`)
   - 업로드 날짜 수정 (형식 `YYYY.MM.DD`)
   - 내용 수정 (강조 표시 문법은 add-news와 동일: `**볼드**`, `{{red:색상}}`)
   - 이미지 교체 (아래 "이미지 교체" 참고)
4. 변경 내용을 확정하기 전에 "이렇게 바꾸면 될까요?"로 반드시 확인받는다. 확인 전에는 파일을 수정하지 않는다.
5. 확인받은 내용대로 Edit 도구로 해당 게시물 객체를 수정한다. 기존 코드 스타일(따옴표, 들여쓰기, trailing comma)을 그대로 따른다.
6. 변경 후 아래 명령으로 검증한다:
   ```bash
   pnpm exec eslint src/data/news.ts
   pnpm exec tsc -b --noEmit
   ```
7. 에러가 있으면 고치고, 없으면 무엇을 수정했는지 짧게 알려준다.

## 이미지 교체

사용자가 "이미지를 바꾸고 싶다"고 하면, 코드를 수정할 필요 없이 파일만 교체하면 되는 경우가 대부분이다.

- `image` 필드가 **지정되어 있지 않은** 게시물(대부분의 경우): `public/news/{id}.{jpg|jpeg|png|webp}` 파일을 새 이미지로 덮어쓰면 된다.
  - 어떤 확장자로 저장되어 있는지 모르면 `ls public/news/{id}.*`로 확인해서 정확한 파일명을 알려준다.
  - 새 이미지의 확장자가 기존과 다르면(예: 기존은 `.jpg`인데 새 이미지가 `.png`), 기존 파일을 지우고 새 확장자로 저장해야 한다는 점도 함께 안내한다(둘 다 있으면 `.jpg`가 먼저 탐색되어 새 `.png`가 무시됨).
- `image` 필드가 **직접 지정되어 있는** 게시물: 데이터에 적힌 그 경로의 파일을 그대로 교체하면 된다.
- 실제 파일 교체(덮어쓰기)는 사용자가 직접 하는 것이므로, 이 스킬에서 이미지 파일을 Bash로 옮기거나 지우거나 만들지 않는다. 정확한 경로/파일명만 안내한다.

## 하지 말 것

- 확인 없이 바로 수정하지 않는다. 대상이 애매하거나 후보가 여러 개일 때 임의로 하나를 골라 진행하지 않는다.
- 게시물의 `id`는 절대 바꾸지 않는다.
- `src/components/NewsImage.tsx`, `src/components/AdjacentPostNav.tsx`, `src/routes/news/index.tsx`, `src/routes/news/$id.tsx`는 수정하지 않는다.
- 이미지 파일 자체를 Bash로 옮기거나 삭제하거나 새로 만들지 않는다. 경로 안내만 한다.
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
