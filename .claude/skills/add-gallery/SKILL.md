# Gallery 게시물 추가

사용자가 `public/gallery/` 폴더에 이미지 원본 파일을 미리 넣어두면, 그 파일들을 찾아서
`src/data/gallery.ts`에 맞는 이름으로 정리하고 게시물 데이터를 생성하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 필요한 정보만 물어본다.

## 1. 신규 이미지 탐지

1. `src/data/gallery.ts`를 읽어 기존 게시물의 `id` 목록과 다음에 쓸 id(기존 최댓값 + 1)를 파악한다.
2. `public/gallery/`의 파일 목록을 확인한다. 파일명이 `{기존 id}-{숫자}.(jpg|jpeg|png|webp)` 패턴과 정확히 일치하는 파일은 이미 등록된 게시물의 이미지이므로 건너뛴다.
3. 그 외 파일(사용자가 방금 넣은 원본 — `IMG_1234.jpg`, `사진1.png` 처럼 규칙과 무관한 이름)을 "신규 이미지"로 취급한다. 신규 이미지가 하나도 없으면 사용자에게 "public/gallery에 새로 추가된 이미지가 없습니다"라고 안내하고 종료한다.

## 2. 게시물로 그룹핑

신규 이미지가 여러 장이면, 몇 개의 게시물로 나눌지와 각 게시물에 어떤 파일이 몇 장씩 들어가는지 사용자에게 물어본다(파일명만으로는 어떤 사진이 같은 게시물인지 알 수 없으므로 반드시 확인받는다). 신규 이미지가 1장뿐이면 게시물 1개, 이미지 1장으로 간주하고 바로 다음 단계로 넘어간다.

한 게시물에 이미지가 여러 장이면, 어떤 파일을 1번(목록 썸네일/캐러셀 첫 이미지)으로 할지 반드시 사용자에게 지정받는다(임의로 정하지 않음). 나머지 순서는 파일의 수정 시각 오름차순으로 제안하고 사용자에게 맞는지 확인한다.

## 3. 게시물별 정보 입력

`$ARGUMENTS`에 제목이 있고 신규 게시물이 1개뿐이면 그 값을 제목으로 쓴다. 그 외에는 게시물마다 아래를 물어본다.

1. **제목** — 필수. 임의로 지어내지 않는다.
2. **업로드 날짜** — 선택. 형식은 `YYYY.MM.DD`. 지정하지 않으면 오늘 날짜를 이 형식으로 변환해 바로 채운다(물어보지 않음).
3. **설명 텍스트** — 선택. 상세 페이지에서 이미지 전부 아래에 표시됨. 없으면 `text` 필드 자체를 생략한다. 강조 표시 문법 안내:
   - 볼드: `**텍스트**`
   - 색상: `{{red:텍스트}}` (색상 이름은 아무 CSS color 키워드나 가능, 예: red, blue)

## 4. 파일 정리 + 데이터 삽입

각 신규 게시물마다:

1. 다음 id를 배정한다(게시물이 여러 개면 순서대로 1씩 증가).
2. Bash `mv`로 해당 게시물의 이미지 파일들을 `public/gallery/{id}-1.{확장자}`, `public/gallery/{id}-2.{확장자}`... 순서로 이름을 바꾼다(2번 단계에서 정한 순서대로 번호를 매긴다). 확장자는 원본 포맷 그대로 유지하되(화질/포맷 변환 금지 — 원본은 상세 페이지에서 그대로 노출됨) **항상 소문자로 정규화한다**(예: `.JPG` → `.jpg`). `GalleryImage` 컴포넌트가 소문자 확장자(`jpg`/`jpeg`/`png`/`webp`)만 탐색하므로, 대문자로 남겨두면 macOS 등 대소문자 구분 없는 환경에서는 문제없이 보이다가 대소문자를 구분하는 배포 서버에서 이미지가 깨진다.
3. 각 이미지마다 목록용 썸네일을 생성한다:
   ```bash
   node scripts/generate-gallery-thumbnail.mjs public/gallery/{id}-{n}.{확장자} public/gallery/{id}-{n}-thumb.jpg
   ```
   (예: id가 5고 이미지가 2장이면 `public/gallery/5-1-thumb.jpg`, `public/gallery/5-2-thumb.jpg`를 생성)
4. `src/data/gallery.ts`를 읽고 새 게시물 객체를 만든다. 필드 순서는 `id` → `title` → `uploadDate` → `imageCount` → `text`(있는 경우만). 기존 코드 스타일(따옴표, 들여쓰기, trailing comma)을 그대로 따른다.
5. Edit 도구로 배열 **맨 앞**에 삽입한다(최신 게시물이 맨 앞에 오는 기존 정렬 규칙). 여러 게시물을 한 번에 추가하는 경우, 사용자가 알려준 순서대로 앞쪽에 나란히 넣는다(가장 나중에 언급된 것이 맨 앞).

## 5. 검증

```bash
pnpm exec eslint src/data/gallery.ts
pnpm exec tsc -b --noEmit
```

에러가 있으면 고치고, 없으면 어떤 게시물을 몇 번 id로, 이미지 몇 장과 함께 추가했는지 사용자에게 짧게 알려준다. 화면 확인은 `pnpm dev` 실행 후 Gallery 페이지에서 볼 수 있다고 안내한다.

## 하지 말 것

- `src/components/GalleryImage.tsx`, `src/components/GalleryCarousel.tsx`, `src/routes/gallery/index.tsx`, `src/routes/gallery/$id.tsx`, `scripts/generate-gallery-thumbnail.mjs`는 이미 이 데이터를 렌더링/처리하도록 연결되어 있으므로 수정하지 않는다.
- 썸네일 생성을 건너뛰지 않는다. 썸네일이 없으면 목록 페이지에서 원본 대용량 파일이 그대로 로드된다.
- 제목을 사용자가 안 주면 임의로 지어내지 말고 반드시 물어본다.
- 어떤 이미지가 같은 게시물인지 확인 없이 임의로 묶지 않는다.
- 이미지가 여러 장이면 1번 이미지를 사용자 확인 없이 임의로 정하지 않는다.
- 파일 리네임 시 확장자를 대문자로 남겨두지 않는다(`.JPG`, `.PNG` 등은 반드시 소문자로 변환).
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
