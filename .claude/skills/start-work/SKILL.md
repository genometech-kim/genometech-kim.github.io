# 작업 시작하기

홈페이지 작업 전, 사용자 상황에 맞게 개발 환경과 git 브랜치를 준비해주는 스킬.
먼저 아래 세 가지 중 어디에 해당하는지부터 물어본다.

```
1. 홈페이지 작업이 처음이신가요?
2. 작업한 적이 있고, 새로운 작업을 시작하실 건가요?
3. 이전에 하던 작업을 이어서 하실 건가요?
```

## 1. 처음이신 경우

1. `git --version`, `node -v`, `pnpm -v`를 차례로 확인한다.
   - 명령어를 못 찾으면(설치 안 됨) README의 "시작하기 전에" 섹션 내용대로 안내한다(Node.js는 nodejs.org에서 LTS 설치, pnpm은 `corepack enable && corepack prepare pnpm@latest --activate`). 사용자가 직접 설치할 시간을 준 뒤, 완료했다고 하면 다시 버전 확인으로 넘어간다.
2. 셋 다 정상 확인되면 `pnpm install`을 실행한다.
3. 완료되면 "이제 실제 작업을 시작해볼까요?"라고 물어보고, **2. 새로운 작업을 시작하는 경우** 절차로 자연스럽게 이어간다.

## 2. 새로운 작업을 시작하는 경우

1. `git status`로 현재 상태를 확인한다. 커밋되지 않은 변경사항이 있으면 무엇을 할지 먼저 물어본다(커밋할지, 버릴지, 그대로 새 브랜치로 옮길지) — 임의로 버리지 않는다.
2. `git checkout develop`으로 전환하고 `git pull origin develop`으로 최신화한다.
3. 어떤 작업을 할 건지 간단히 물어보고, 그 내용을 바탕으로 브랜치 이름을 제안한다(`feat/기능-이름` 또는 `fix/버그-이름` 형식). 사용자가 다른 이름을 원하면 그대로 따른다.
4. `git checkout -b <제안한 브랜치명>`으로 새 브랜치를 만든다.
5. 이제 작업을 시작해도 된다고 안내한다.

## 3. 이전 작업을 이어서 하는 경우

1. `git branch --show-current`로 현재 브랜치를 확인한다.
2. 현재 브랜치가 `main` 또는 `develop`이면: 곧바로 작업하면 안 된다고 안내하고, 이어서 할 작업이 있던 브랜치 이름을 물어본 뒤 `git checkout <브랜치명>`으로 전환한다. 기억이 안 난다고 하면 `git branch`로 로컬 브랜치 목록을 보여주고 고르게 한다.
3. 이미 `feat/*`나 `fix/*` 같은 작업 브랜치에 있으면 "지금 `<브랜치명>` 브랜치인데 맞나요?"라고 확인만 하고 넘어간다.
4. 원격에 더 최신 내용이 있을 수 있으니 `git pull origin <브랜치명>`을 제안한다(실패하거나 브랜치가 원격에 없으면 그냥 넘어간다).

## 공통: develop/main에서 직접 작업 금지

이 스킬을 거치지 않고 바로 코드 수정을 요청받았는데 현재 브랜치가 `main`이나 `develop`이면, 수정하기 전에 먼저 멈추고 이 스킬의 "2. 새로운 작업을 시작하는 경우" 절차(또는 "3. 이전 작업 이어서")를 안내한다. `develop`/`main`에는 직접 커밋하지 않는다.

## 하지 말 것

- 커밋되지 않은 변경사항을 확인 없이 버리거나 새 브랜치로 임의로 옮기지 않는다.
- `main`/`develop` 브랜치에서 직접 파일을 수정하거나 커밋하지 않는다.
- git commit이나 push는 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
