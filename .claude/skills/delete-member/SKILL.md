# 멤버 항목 삭제

Member 페이지 데이터(`src/data/members.ts`)에서 멤버를 삭제하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 되돌리기 어려운 작업이므로 반드시 대상 확인을 거친 뒤에만 삭제한다.

## 입력

`$ARGUMENTS`에 삭제할 멤버 이름(한글 또는 영문)이 있으면 그것을 사용한다. 없으면 물어본다.

```
/delete-member 박지훈
/delete-member Jihoon Park
```

## 절차

1. `src/data/members.ts`를 읽는다.
2. 입력받은 이름으로 `nameKo`/`nameEn`을 대조해 대상을 찾는다(부분 일치 허용, 대소문자 무시).
   - 일치하는 멤버가 없으면, 이름 철자를 다시 확인해달라고 요청한다. 임의로 비슷한 멤버를 골라 진행하지 않는다.
   - 일치하는 멤버가 여러 명이면, 후보 목록(이름/직함/이메일)을 보여주고 어떤 멤버인지 선택해달라고 물어본다.
3. 대상이 하나로 정해지면, 그 멤버의 정보(이름(한/영), 직함, 이메일, 사진 지정 여부)를 그대로 보여주며 "이 멤버가 맞나요? 삭제하면 되돌리기 어렵습니다" 같은 문구로 반드시 확인을 받는다.
4. 사용자가 명확히 확인한 경우에만 Edit 도구로 `members` 배열에서 해당 객체를 제거한다. 확인 전에는 절대 파일을 수정하지 않는다.
5. 변경 후 아래 명령으로 검증한다:
   ```bash
   pnpm exec eslint src/data/members.ts
   pnpm exec tsc -b --noEmit
   ```
6. 에러가 있으면 고치고, 없으면 어떤 멤버를 삭제했는지 짧게 알려준다.
7. 삭제된 멤버에 연결된 사진 파일이 있는지 확인한다.
   - `photo` 필드가 지정되어 있었다면 그 경로.
   - 없었다면 `public/members/{email 아이디}.{jpg|jpeg|png|webp}`를 순서대로 확인(email이 없었다면 사진 파일도 없는 것이므로 건너뛴다).
   - 실제로 파일이 존재하면(`ls` 등으로 확인), 사용자에게 "사진 파일(`public/members/파일명`)도 같이 삭제할까요?"라고 물어본다.
   - 사용자가 삭제를 확인한 경우에만 Bash로 그 파일 하나만 정확히 삭제한다(`rm public/members/파일명` 형태로 경로를 명시하고, 와일드카드나 `-r`/`-f` 옵션, 여러 파일 삭제는 절대 쓰지 않는다).
   - 파일이 없거나 사용자가 원치 않으면 삭제하지 않는다.

## 하지 말 것

- 확인 없이 바로 삭제하지 않는다. 이름이 애매하거나 후보가 여러 명일 때 임의로 하나를 골라 삭제하지 않는다.
- `src/components/MemberCard.tsx`, `src/components/Pagination.tsx`, `src/routes/members/member.tsx`는 수정하지 않는다.
- 사진 파일 삭제는 반드시 별도로 확인받은 뒤, 정확히 그 파일 하나만 삭제한다. 와일드카드 삭제나 확인 없는 삭제는 하지 않는다.
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
