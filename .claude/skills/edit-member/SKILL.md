# 멤버 항목 수정

Member 페이지 데이터(`src/data/members.ts`)에서 기존 멤버 정보를 수정하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 무엇을 바꿀지 명확히 확인한 뒤에만 수정한다.

## 입력

`$ARGUMENTS`에 수정할 멤버의 이름(한글 또는 영문)이 있으면 그것을 사용한다. 없으면 물어본다.

```
/edit-member 박지훈
/edit-member Jihoon Park
```

## 절차

1. `src/data/members.ts`를 읽는다.
2. 입력받은 이름으로 `nameKo`/`nameEn`을 대조해 대상을 찾는다(부분 일치 허용, 대소문자 무시).
   - 일치하는 멤버가 없으면 이름 철자를 다시 확인해달라고 요청한다. 임의로 비슷한 멤버를 골라 진행하지 않는다.
   - **동명이인 확인**: 이름이 일치하는 멤버가 여러 명이면, 후보 목록을 이름뿐 아니라 직함/이메일까지 함께 보여주고 어떤 멤버인지 선택해달라고 물어본다. 이름만 보고 임의로 첫 번째 후보를 고르지 않는다. 사용자가 직함이나 이메일 같은 추가 정보를 먼저 언급했다면 그 정보로 후보를 좁혀서 확인받는다.
3. 대상이 하나로 정해지면, 현재 정보(이름(한/영), 직함, 이메일, 사진 지정 여부)를 보여주고 무엇을 바꿀지 물어본다. 가능한 변경 종류:
   - 이름(한글/영문) 수정
   - 직함/과정 수정
   - 이메일 수정 (주의: 이메일을 바꾸면 자동 추론되던 사진 경로 `public/members/{기존 이메일 아이디}.{ext}`도 더 이상 안 맞게 된다는 점을 안내 — 아래 "사진 교체" 참고)
   - 사진 교체 (아래 "사진 교체" 절차 참고)
4. 변경 내용을 확정하기 전에 "이렇게 바꾸면 될까요?"로 반드시 확인받는다. 확인 전에는 파일을 수정하지 않는다.
5. 확인받은 내용대로 Edit 도구로 해당 멤버 객체를 수정한다. 기존 코드 스타일(따옴표, 들여쓰기, trailing comma)을 그대로 따른다.
6. 변경 후 아래 명령으로 검증한다:
   ```bash
   pnpm exec eslint src/data/members.ts
   pnpm exec tsc -b --noEmit
   ```
7. 에러가 있으면 고치고, 없으면 무엇을 수정했는지 짧게 알려준다.

## 사진 교체

사용자가 "사진을 바꾸고 싶다"고 하면, 코드를 수정할 필요 없이 파일만 교체하면 되는 경우가 대부분이다.

- `photo` 필드가 **지정되어 있지 않은** 멤버(대부분의 경우): `public/members/{이메일 아이디}.{jpg|jpeg|png|webp}` 파일을 새 사진으로 덮어쓰면 된다. 예를 들어 이메일이 `abc@hanyang.ac.kr`이면 `public/members/abc.jpg` (또는 실제 존재하는 확장자 파일)를 교체.
  - 어떤 확장자로 저장되어 있는지 모르면 `ls public/members/{이메일 아이디}.*`로 확인해서 정확한 파일명을 알려준다.
  - 새 사진의 확장자가 기존과 다르면(예: 기존은 `.jpg`인데 새 사진이 `.png`), 기존 파일을 지우고 새 확장자로 저장해야 한다는 점도 함께 안내한다(둘 다 있으면 `.jpg`가 먼저 탐색되어 새 `.png`가 무시됨).
- `photo` 필드가 **직접 지정되어 있는** 멤버: 데이터에 적힌 그 경로의 파일(`public/` 기준 상대경로)을 그대로 교체하면 된다.
- 실제 파일 교체(덮어쓰기)는 사용자가 직접 하는 것이므로, 이 스킬에서 이미지 파일을 Bash로 옮기거나 지우거나 만들지 않는다. 정확한 경로/파일명만 안내한다.

## 하지 말 것

- 확인 없이 바로 수정하지 않는다. 대상이 애매하거나(동명이인 포함) 후보가 여러 명일 때 임의로 하나를 골라 진행하지 않는다.
- `src/components/MemberCard.tsx`, `src/components/Pagination.tsx`, `src/routes/members/member.tsx`는 수정하지 않는다.
- 사진 파일 자체를 Bash로 옮기거나 삭제하거나 새로 만들지 않는다. 경로 안내만 한다.
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
