# Publication 논문 수정

Publication 페이지 데이터(`src/data/publication.ts`)에서 기존 논문 정보를 수정하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 무엇을 바꿀지 명확히 확인한 뒤에만 수정한다.

## 배경 지식

- 이 데이터는 `id` 같은 고유 번호가 없다. 목록의 번호는 배열 순서에서 자동으로 계산되므로(배열 첫 항목이 가장 큰 번호), 논문을 찾을 때 화면에 보이는 번호가 아니라 **제목/저널명/연도**로 대상을 특정한다.
- `authors`는 하나의 문자열이고, `BOLD_AUTHORS` 배열에 있는 문자열이 포함되어 있으면 자동으로 볼드 처리된다.

## 입력

`$ARGUMENTS`에 수정할 논문의 제목 일부가 있으면 그것을 사용한다. 없으면 물어본다.

```
/edit-publication CRISPR-based diagnostic
```

## 절차

1. `src/data/publication.ts`를 읽는다.
2. 입력받은 값으로 `title`을 대조해 대상을 찾는다(부분 일치 허용, 대소문자 무시).
   - 일치하는 논문이 없으면 다시 확인해달라고 요청한다. 임의로 비슷한 논문을 골라 진행하지 않는다.
   - 후보가 여러 개면 목록(제목/저널명/연도)을 보여주고 선택해달라고 물어본다.
3. 대상이 하나로 정해지면, 현재 정보(제목, 저널명, 연도, 저자, 링크)를 보여주고 무엇을 바꿀지 물어본다. 가능한 변경 종류:
   - 제목 수정
   - 저널명 수정
   - 연도 수정
   - 저자 문자열 수정 (원문 그대로 붙여넣어 달라고 안내. 임의로 재구성하지 않는다)
   - 링크(URL) 수정
   - 위치 이동 (연도가 바뀌어서 배열 순서/번호가 안 맞게 된 경우 등. 사용자가 원할 때만 옮기고, 애매하면 그대로 둔다)
4. 저자 문자열을 수정하는 경우, add-publication과 동일하게 새로운 볼드 표기 형태가 필요한지 확인하고 임의로 `BOLD_AUTHORS`를 바꾸지 않는다.
5. 변경 내용을 확정하기 전에 "이렇게 바꾸면 될까요?"로 반드시 확인받는다. 확인 전에는 파일을 수정하지 않는다.
6. 확인받은 내용대로 Edit 도구로 해당 논문 객체를 수정한다. 기존 코드 스타일(따옴표, 들여쓰기, trailing comma)을 그대로 따른다.
7. 변경 후 아래 명령으로 검증한다:
   ```bash
   pnpm exec eslint src/data/publication.ts
   pnpm exec tsc -b --noEmit
   ```
8. 에러가 있으면 고치고, 없으면 무엇을 수정했는지 짧게 알려준다.

## 하지 말 것

- 확인 없이 바로 수정하지 않는다. 대상이 애매하거나 후보가 여러 개일 때 임의로 하나를 골라 진행하지 않는다.
- 저자 문자열을 임의로 요약/재구성하지 않는다.
- `BOLD_AUTHORS`에 새 표기를 사용자 확인 없이 임의로 추가/수정하지 않는다.
- `src/routes/publication/index.tsx`는 수정하지 않는다.
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
