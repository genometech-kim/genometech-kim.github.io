# Publication 논문 삭제

Publication 페이지 데이터(`src/data/publication.ts`)에서 논문을 삭제하는 스킬.
코드나 파일 경로 얘기는 하지 않는다. 되돌리기 어려운 작업이므로 반드시 대상 확인을 거친 뒤에만 삭제한다.

## 배경 지식

- 이 데이터는 `id` 같은 고유 번호가 없다. 목록의 번호는 배열 순서에서 자동으로 계산되므로(배열 첫 항목이 가장 큰 번호), 논문을 찾을 때 화면에 보이는 번호가 아니라 **제목/저널명/연도**로 대상을 특정한다.
- 다른 게시판(News/Gallery)과 달리 이 데이터는 고유 id가 없으므로, 하나를 삭제하면 그 뒤 논문들의 **표시 번호는 자연스럽게 하나씩 당겨진다**(이건 정상 동작이며 별도로 재정렬 로직이 필요 없다).

## 입력

`$ARGUMENTS`에 삭제할 논문의 제목 일부가 있으면 그것을 사용한다. 없으면 물어본다.

```
/delete-publication CRISPR-based diagnostic
```

## 절차

1. `src/data/publication.ts`를 읽는다.
2. 입력받은 값으로 `title`을 대조해 대상을 찾는다(부분 일치 허용, 대소문자 무시).
   - 일치하는 논문이 없으면 다시 확인해달라고 요청한다. 임의로 비슷한 논문을 골라 진행하지 않는다.
   - 후보가 여러 개면 목록(제목/저널명/연도)을 보여주고 선택해달라고 물어본다.
3. 대상이 하나로 정해지면, 그 논문의 정보(제목, 저널명, 연도, 저자, 링크)를 그대로 보여주며 "이 논문이 맞나요? 삭제하면 되돌리기 어렵습니다" 같은 문구로 반드시 확인을 받는다.
4. 사용자가 명확히 확인한 경우에만 Edit 도구로 `publications` 배열에서 해당 객체를 제거한다. 확인 전에는 절대 파일을 수정하지 않는다.
5. 변경 후 아래 명령으로 검증한다:
   ```bash
   pnpm exec eslint src/data/publication.ts
   pnpm exec tsc -b --noEmit
   ```
6. 에러가 있으면 고치고, 없으면 어떤 논문을 삭제했는지 짧게 알려준다.

## 하지 말 것

- 확인 없이 바로 삭제하지 않는다. 대상이 애매하거나 후보가 여러 개일 때 임의로 하나를 골라 삭제하지 않는다.
- `src/routes/publication/index.tsx`는 수정하지 않는다.
- git commit은 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
